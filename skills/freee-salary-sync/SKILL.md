# freee-salary-sync: 正社員の日次人件費 → 売上シート「社員」列 転記

指定した給与月の freee 人事労務データ（正社員のみ）から、**1日ごとの社員人件費**を算出し、各直営店スプレッドシートの**「社員」列**に転記する決定論的 CLI。

**実行時に AI は一切使わない。** 取得（内部 API・Cookie 認証）・算出・書込はすべて `src/index.js` が決定論的に行う。アルバイト列を埋める `airregi-sales-sync` の社員版。

---

## 起動手順（決定論的）

ユーザー発話から **給与対象の年・月** を決める（「5月」→ その年の5月。年指定が無ければ当年）。スキルディレクトリで実行する:

```bash
cd <このスキルのディレクトリ> && node src/index.js <年> <月>
```

例:
- 2026年5月分: `node src/index.js 2026 5`
- 書込前に算出だけ確認: `node src/index.js 2026 5 --dry-run`

freee の「5月給与」は賃金計算期間（例 4/3〜5/2）の実日付に対応する行へ書き込む。月をまたぐ期間も各日付の年タブへ正しく振り分く。

---

## 算出仕様（確定）

1日の「社員」値 ＝ その店舗の正社員全員（`working_hours_system_name === "正社員"`）の合算。各正社員について:

- **固定日割り（出勤日のみ計上）** ＝（支給総額 − 残業代合計 ＋ 社会保険の会社負担）÷ 実労働日数
- **当日残業代** ＝ freee 月次残業代を当日の残業実績（分）で按分（固定残業代/みなし・深夜を内包）

店舗対応は従業員番号の接頭辞（`Kobe`→神戸 / `Umeda`→梅田 / `Shinsaibashi`→心斎橋）。

---

## 結果報告

CLI の標準出力（店舗別 ✓/✗）をそのままユーザーに報告する。終了コード 0=全店舗成功、1=1店舗以上失敗。

```
  ✓ 2026年5月 saude 神戸店   正社員1名 → 社員列 書込 30日
  ✓ 2026年5月 saude 梅田店   正社員2名 → 社員列 書込 30日
  ✓ 2026年5月 saude 心斎橋店 正社員2名 → 社員列 書込 30日
```

✗ が出たら、その行の原因（freee 未ログイン／secret 不一致／社員列なし 等）を伝える。`--dry-run` で算出内訳を確認できる。

---

## 前提（初回のみ・README 参照）

1. Chrome で freee 人事労務にログイン済み（セッション Cookie を再利用）。
2. 一度だけ `security find-generic-password -ws "Chrome Safe Storage"` を実 Terminal で「常に許可」。
3. `config.json` 作成（`freee.companyId` / `gas` / `stores[].numPrefix`）。
4. 共用 GAS（`airregi-sales-sync` と同一）に `gas/Code.gs`（社員日次パス追加版・後方互換）を反映して再デプロイ。

---

## やらないこと

- 社員人件費の数値をスキル（Claude）側で計算・加工しない（CLI が算出）。
- config・Cookie・secret を出力・ログに残さない。
- アルバイト人件費は扱わない（`airregi-sales-sync` が担当）。
